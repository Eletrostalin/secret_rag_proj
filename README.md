Архитектура и логика работы

Проект разделён на backend и frontend (ui).
Все контейнеры описаны в Docker Compose.

Общий пайплайн запроса
	1.	Клиент отправляет вопрос через Gradio-интерфейс.
	2.	Gradio (ui) пересылает его на FastAPI (backend).
	3.	FastAPI определяет тип запроса (NORMAL или QUOTE).
	4.	Если NORMAL:
	•	Запускается цепочка: классификация → переформулировка → расширение → поиск по индексам → реранкинг → сборка контекста → LLM-генерация.
	5.	Если QUOTE:
	•	Извлекаются подходящие фрагменты из БД и возвращаются дословно.

⸻
Система реализует многошаговый RAG-пайплайн. Основные этапы:
	1.	Классификация запроса
	•	Проверяем, хочет ли пользователь просто получить точный текст закона (QUOTE) или нормальный ответ (NORMAL).
	•	Используем LLM для классификации (NORMAL / QUOTE).
	2.	Обработка QUOTE-запроса
	•	При QUOTE извлекаем топ-N релевантных фрагментов (чанков) напрямую из БД.
	•	Прогоняем их через дополнительный LLM-фильтр для точности.
	•	Возвращаем дословные тексты.
	3.	Обработка NORMAL-запроса
	•	Вопрос переписывается для улучшенного поиска (query rewriting).
	•	Добавляются синонимы (query expansion).
	•	Выполняем поиск по базе с помощью BM25 (retrieval.py).
	•	Полученные результаты реранкуются через LLM (reranker.py).
	•	Из выбранных чанков собираем контекст (context_builder.py).
	•	Генерируем итоговый ответ через OpenAI.
	4.	BM25-поиск
	•	Все тексты предварительно индексируются в локальном BM25-индексе.
	•	Индекс хранится и загружается при старте сервиса.
	5.	Хранение и структура чанков
	•	Чанки хранятся в Postgres.
	•	Каждый чанк имеет номер части, секции и оригинальный текст.
	6.	Парсинг и инжест
	•	Документы парсятся из PDF.
	•	Делятся на чанки (chunker.py, llm_chunker.py).
	•	Сохраняются в БД с привязкой к структуре документа.
	•	Для продвинутого разбиения можем использовать LLM.

Структура проекта и назначение модулей

Корень
	•	.env и .env.example – конфигурация переменных окружения
	•	requirements.txt – зависимости
	•	docker-compose.local.yml – Compose-файл для локального развёртывания
	•	docker-compose_remote.yml – Compose-файл для теста через ngrok
	•	nginx.conf – конфиг для проксирования запросов
	•	README.md – этот файл

⸻

/backend

backend/Dockerfile

Инструкция сборки образа для FastAPI-приложения.
Ставит зависимости и запускает Uvicorn.

main.py

Точка входа FastAPI-приложения.
Инициализирует роуты и сервисы.

config.py

Загружает переменные окружения (например, ключи и URL базы).

prompts.py

Хранит все шаблоны системных сообщений для вызова LLM.

⸻

/api/routes
	•	ask.py — маршрут обработки основного запроса /ask
	•	upload.py — роут для загрузки новых документов и разделов в систему

⸻

/api/services
	•	classifier.py — классифицирует вопрос на NORMAL/QUOTE
	•	context_builder.py — собирает найденные чанки в единый контекст
	•	filter_chunks_via_llm.py — фильтрует чанки для QUOTE-запросов через LLM
	•	llm_client.py — общение с OpenAI API
	•	prompt_engineering.py — шаблонизация промптов
	•	reranker.py — улучшает порядок результатов поиска
	•	retrieval.py — основной поиск по базе (BM25, фильтрация)

⸻

/db
	•	database.py — конфигурация и подключение к Postgres
	•	indexer.py — логика построения BM25-индекса
	•	models.py — SQLAlchemy-модели таблиц
	•	schemas.py — Pydantic-схемы для валидации и сериализации данных

⸻

/ingestion
	•	chunker.py — делит документы на логические блоки
	•	embedder.py — создаёт эмбеддинги для чанков
	•	ingest_service.py — orchestration импорта документов
	•	llm_chunker.py — продвинутый чанкер через LLM
	•	parser.py — парсинг PDF и других форматов

⸻

/utils
	•	logger.py — настройка логирования
	•	__init__.py — для структуры пакета
